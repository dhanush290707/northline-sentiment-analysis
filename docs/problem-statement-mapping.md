# Problem statement mapping

Problem statement 24CC3014-P072, Amazon Comprehend Sentiment Analysis on Customer Feedback. Teams T072, T213, and T354.

The use cases on the statement are sentiment classification of customer feedback and routing negative feedback for escalation. Product reviews are the feedback records. The two bottlenecks are shown rather than claimed to be solved.

| PS Requirement | Implemented Feature | AWS Service | Code Location | Demonstration |
| --- | --- | --- | --- | --- |
| Classify sentiment in customer feedback | A purchased product can receive a star rating and a written review. The API detects the language and calls document sentiment. The label and four confidence scores are stored with the review. | Amazon Comprehend `DetectDominantLanguage` and `DetectSentiment`; result stored in DynamoDB | [backend/src/routes/reviews.js](../backend/src/routes/reviews.js), [backend/src/services/comprehend.js](../backend/src/services/comprehend.js) | Sign in, order a product, submit "Excellent phone. The camera quality is amazing." Open the same review on the shop desk and read the sentiment and scores. |
| Route negative feedback for escalation | If the label is `NEGATIVE` and the negative score is at least `NEGATIVE_ESCALATION_THRESHOLD` (default 0.75), the review is stored as `ESCALATED` / `HIGH`. Weaker negatives and mixed reviews are `OPEN`. Positive and neutral reviews are `NONE`. | Comprehend supplies the scores. Escalation is application code, not a Comprehend feature. DynamoDB stores the status. | [backend/src/services/escalation.js](../backend/src/services/escalation.js) | Submit "The battery is terrible and the phone overheats." On the desk, the threshold is printed and the review appears under Escalated when the negative score clears it. |
| Shop owner can work the escalated queue | The desk lists escalated reviews and can mark one reviewed, resolved, or escalated, and can change priority. Leaving `ESCALATED` updates the counter. | API Gateway JWT authorizer, Lambda group check, DynamoDB | [backend/src/routes/admin.js](../backend/src/routes/admin.js), [frontend/src/pages/admin/ReviewDetailPage.jsx](../frontend/src/pages/admin/ReviewDetailPage.jsx) | Sign in as a user in the Cognito `admins` group. Open an escalated review and choose Mark resolved. Confirm a customer token receives 403 on `GET /admin/dashboard`. |
| Sentiment is visible as a business dashboard | Totals, percentage distribution, sentiment over time, and per-product negative share. Customers do not receive scores on the product page. | DynamoDB counters and review queries, rendered in the React desk | [frontend/src/pages/admin/DashboardPage.jsx](../frontend/src/pages/admin/DashboardPage.jsx), [backend/src/mappers.js](../backend/src/mappers.js) | Compare the product page, which shows stars and text, with the desk, which shows scores and status. |
| Domain-specific language may be misclassified | Electronics reviews about battery backup, HDR, night mode, ANC, and transparency mode are accepted as ordinary text. The desk shows the original sentence beside the scores and any English aspects. No custom model rewrites the label. | Comprehend `DetectSentiment` and, for English, `DetectTargetedSentiment` | [docs/sentiment-analysis.md](sentiment-analysis.md), [frontend/src/pages/admin/ReviewDetailPage.jsx](../frontend/src/pages/admin/ReviewDetailPage.jsx) | Submit "ANC is excellent but transparency mode has noticeable latency." On the review detail, read the sentence next to the four scores and the aspect chips. A surprising label is the bottleneck, left visible. |
| Regional-language support is limited | Document sentiment allows only Comprehend's set, including Hindi. Other Indian languages return 422 and are not stored. Targeted sentiment runs only for English. | Comprehend language detection and `DetectSentiment` | [backend/src/utils/languages.js](../backend/src/utils/languages.js) | Submit a short Hindi review and confirm a real sentiment with `SKIPPED_NOT_ENGLISH`. Submit a Tamil sentence and confirm the 422 and the absence of a new review. |
| Customers can produce the feedback the model scores | Catalog, search, filters, product detail, cart, checkout, orders, profile, and reviews. | Cognito for identity, API Gateway and Lambda for the shop, DynamoDB for products, orders, and reviews | [frontend/src/pages](../frontend/src/pages), [backend/src/routes](../backend/src/routes) | Walk from the home page through checkout and a review without using the admin account. |
| Analysis is not called from the browser, and secrets stay off the client | The frontend has the pool id, client id, region, and API URL only. Comprehend and DynamoDB clients exist only in the backend. | IAM role on Lambda; Cognito app client without a secret | [frontend/src/services/api.js](../frontend/src/services/api.js), [infrastructure/template.yaml](../infrastructure/template.yaml) | Search the frontend for `Comprehend` or an access-key variable. Both are absent. The network panel shows calls only to Cognito and the Northline API. |
